# Telegram-бот Wildberries FBS

Бот использует текущий Docker-образ и читает `/app/config.py`, подключённый с VPS. В модуле должны быть определены `API_TOKEN`, `WB_API` и `interval` в секундах. GitHub Actions сохраняет существующие secrets, подключение config.py и публикацию образа в GHCR.

После старта контейнера мониторинг остановлен. Отправьте `/start`, чтобы запустить его. Команды `/stop`, `/status`, `/check`, `/chatid` и `/help` останавливают мониторинг, показывают состояние, проверяют WB API, показывают ID чата и выводят справку соответственно. Первый успешный опрос сохраняет текущие заказы и статусы как исходный снимок без уведомлений о старых заказах.

Обычные FBS-сборочные задания отслеживаются методами `GET /api/v3/orders` и `POST /api/v3/orders/status`. Уведомления используют поля `supplierStatus` и `wbStatus` согласно документации Wildberries Marketplace API. Метод истории `/api/v3/orders/status/history` предназначен для трансграничных заказов и не используется как общий источник статусов.

Файл SQLite находится в контейнере по пути `/data/wb_tg_bot.sqlite3`. Оба workflow подключают именованный Docker volume `wb_tg_bot_data:/data`; он переживает остановку и пересоздание контейнера. При ручном запуске используйте тот же volume: `-v wb_tg_bot_data:/data`.

Для локального запуска установите зависимости из `wb_tg_bot/requirements.txt`, поместите `config.py` рядом с `wb_tg_bot.py` в каталоге `wb_tg_bot/`. При необходимости задайте переменную `WB_BOT_DB` для изменения пути к базе.
